Kill Chain Architecture

How the five stages flow across the MCP tool layer, the A2A trust boundary, and external systems.

Defended Run: Why Each Control Works

Control 1: Signed Agent Cards

Every agent card must carry a valid signature from the org trust anchor. The rogue "summariser-helper" has no access to the signing key, so its registration is rejected at the registry layer. Chain breaks at Stage 2.

Control 2: Authorization Policy

The least-privilege policy only allows doc-assistant to call document.summarise and hr-agent to call hr.read. The rogue is not in any allow-list: with this control alone, registration and entry-skill routing still succeed, but the sensitive skill is denied. Chain breaks at Stage 4.

Control 3: Circuit Breaker + Human-in-the-Loop

The high-stakes skill hr.read requires human confirmation, so the rogue cannot complete the exfiltration without a human approving. A circuit breaker (threshold 3) also guards against delegation bursts: this chain makes only two routes, so the breaker never trips here -- it is a backstop, and human-in-the-loop is what breaks this chain. Chain breaks at Stage 4.

Combined

With all three controls active, the chain breaks at Stage 2 -- the earliest possible point. This is defense-in-depth: each control independently stops the kill chain at a different stage.
